# NetSense Development Guide (DEVELOPMENT.md)

> A cross-platform standalone desktop app that automatically matches and applies network profiles (static IP / DHCP / DNS / IPv6) from the current network identity (SSID / gateway MAC / BSSID), with health monitoring (fallback to DHCP on disconnect) and network-triggered automation (set routes / launch apps / run scripts).
> Evolved from `hammerspoon_wifi_switcher` into a **Hammerspoon-free** standalone app.

---

## 1. Tech Stack Decisions

| Item | Choice | Rationale |
|------|--------|-----------|
| Shell | **Tauri v2 (Rust)** + system WebView | Smallest binary (5–15 MB), Rust memory safety, few dependencies; pure-technical first choice |
| Backend | Rust (Core Engine + PAL) | Type safety, cross-platform compilation |
| Frontend | Reuse `hammerspoon_wifi_switcher`'s `editor.html` / `popups.html` | Pure HTML/CSS, talks to backend via Tauri `invoke` (replacing the old `hs.urlevent`) |
| i18n | 5 languages (zh / en / zh-TW / ja / ko) | Borrowed wireguide-plus's `i18n-check.js` key-parity validation, but **code is not reused** (wireguide is Wails+Go, this project is Rust) |

**Tauri vs Wails retrospective**: wireguide-plus uses Wails+Go and could reuse its latency-probe/i18n/release flow; but this project's pure-technical preference is Tauri (tiny binary, memory-safe). Both are valid; this project chose Tauri.

## 4. PAL Contract (src-tauri/src/platform.rs)

```rust
pub trait NetworkPlatform: Send + Sync {
    /// Register an SSID-change callback (event-driven, replacing hs.wifi.watcher)
    fn watch_ssid(&self, cb: Box<dyn Fn(Option<String>) + Send + Sync>);

    fn get_current_ssid(&self) -> Option<String>;
    fn get_status(&self) -> InterfaceStatus;

    fn apply_profile(&self, p: &Profile) -> Result<(), String>;
    fn set_dhcp(&self) -> Result<(), String>;

    // —— Extension 1: independent match conditions ——
    /// default gateway IP → MAC via ARP/neighbor cache
    fn resolve_gateway_mac(&self) -> Option<String>;
    /// BSSID of the current AP
    fn resolve_bssid(&self) -> Option<String>;

    // —— Extension 2: health monitoring ——
    /// ICMP / HTTP probe; in `both` mode the caller decides the verdict
    fn probe(&self, target: &ProbeTarget, timeout_ms: u64) -> Health;

    // —— Extension 3: automation tasks ——
    fn add_route(&self, dest: &str, gw: &str, metric: u32) -> Result<(), String>;
    fn delete_route(&self, dest: &str) -> Result<(), String>;
    fn launch_app(&self, app: &str, args: &[String]) -> Result<(), String>;
    /// constrained by allow-list (only scripts/ or explicitly registered paths); elevated goes through the privilege channel
    fn run_script(&self, path: &str, args: &[String], elevated: bool) -> Result<(), String>;
}
```

Cross-platform implementation notes:

| Capability | macOS | Windows | Linux |
|------------|-------|---------|-------|
| Current SSID | `networksetup -getairportnetwork` / CoreWLAN | `netsh wlan show interfaces` | `nmcli -t -f active,ssid dev wifi` |
| Gateway MAC | `arp -n <gw>` | `arp -a <gw>` | `ip neigh show <gw>` |
| BSSID | `airport -I en0` | `netsh wlan show interfaces` (BSSID) | `iw dev <if> link` |
| Apply static | `networksetup -setmanual` | `netsh interface ip set address` | `nmcli connection modify` |
| ICMP probe | `go-ping` / system ping | same | same |
| Add route | `route add` | `route add` | `ip route add` |
| Launch app | `open <app>` | `start <exe>` | `xdg-open` |

## 5. Match Semantics (src-tauri/src/core/matcher.rs)

- Each Profile's `match` object has optional `ssid` / `gateway_mac` / `bssid`, **independent and AND-related**; undeclared = wildcard.
- A non-`__DEFAULT__` Profile **must declare ≥1** `match` field, otherwise it is excluded from matching.
- When multiple Profiles hit: first "most match conditions wins" (most specific), then `priority` field (higher wins).
- No hit at all → fall back to `__DEFAULT__`.
- Resolution depends on the PAL: `resolve_gateway_mac()`, `resolve_bssid()`.

Example (identifiable by gateway MAC alone; works even if SSID is hidden/renamed):

```json
"OfficeRouter": {
  "match": { "gateway_mac": "aa:bb:cc:dd:ee:ff" },
  "mode": "manual", "ip": "192.168.1.100", "gateway": "192.168.1.1", ...
}
```

## 7. Health Monitoring (src-tauri/src/core/health.rs)

- Modeled on wireguide-plus's **latency probe**, but the action changed from "reconnect tunnel" to "fall back to DHCP" (goal is to keep connectivity alive).
- Probe modes: `icmp` (ping IP), `http` (GET a special URL, recommended `http://cp.cloudflare.com` or a custom health page), `both` (default). Under `both`, a target is declared dead **only when both ICMP and HTTP fail**, avoiding false kills (many networks block ICMP but allow HTTP; also detects captive portals).
- Background `probe loop` (dedicated `std::thread` + `Arc<AtomicBool>` stop flag), **does not block the UI** (fits the "tray reads cache" paradigm).
- Consecutive failures ≥ `retries`: if `health.fallback.enabled` → `set_dhcp()` + run the Profile's `on_revert` + notify; otherwise notify/log only.

## 8. Automation Tasks (src-tauri/src/core/automation.rs)

- netsetman-style "extra" actions: `route` (add/delete), `launch` (open app), `run` (execute script).
- Triggers: `on_apply` (after a Profile takes effect, including first apply), `on_revert` (leaving that SSID / health fallback) — semantics align with wireguide-plus's on-up/on-down hooks.
- **Security boundary**: `route` / `launch` are safe allow-list actions; `run` is **allow-list** constrained (only executes trusted `scripts/` dir or config-explicit registered absolute paths, no arbitrary command injection); elevation reuses the privilege daemon channel.
- A confirmation dialog lists each action to be executed (reusing the original force-apply confirmation style); only proceeds when the user can see it.

## 9. Privilege Model

### 9.1 Current state (P2 landed): sudoers NOPASSWD + allow-list wrapper script

Goal: **changing the network no longer pops an auth dialog every time**, without opening a hole for "arbitrary root commands".

```
GUI process (unprivileged) ──sudo -n──▶ /usr/local/libexec/netsense-priv.sh (root-owned, 0755)
                                 └─ allow-list subcommand + argument-shape validation ──▶ networksetup / route
```

- **Structured operations**: the Rust side only constructs `PrivOp` (`SetManual/SetDhcp/SetDns/SetV6*/RouteAdd/RouteDelete`), encodes it via `PrivOp::encode()` into an `op|arg1|arg2` line, and feeds the script's `--batch` mode over stdin in one shot.
  **User input is never interpolated into a shell command** under any circumstance, eliminating command injection.
- **Script-side second check**: `scripts/netsense-priv.sh` validates the shape of each argument (IPv4 octet 0–255 and rejects leading zeros, prefix 0–128, route target `a.b.c.d[/len]`, DNS as comma-separated IPv4 set, service name non-empty and not starting with `-`); unknown subcommands are rejected outright.
- **Authorization surface**: `/etc/sudoers.d/netsense` authorizes only the script's absolute path (`NOPASSWD:`), not arbitrary user commands; the script and its directory are root-owned and not writable by normal users.
- **Fallback**: if the wrapper script is missing, or `sudo -n` reports "password required / no tty / not allowed", it automatically falls back to `osascript ... with administrator privileges` (the original per-change auth dialog), with no feature breakage.
- **Self-check**: the install script runs `sudo -n <script> --batch` once as the current user at the end to verify the channel works.

Install / uninstall:

```bash
sh scripts/install-priv-helper.sh            # install (needs sudo)
sh scripts/install-priv-helper.sh uninstall  # uninstall
```

### 9.2 Why not a resident privilege daemon directly

A `launchd` resident + Unix socket approach needs its own socket authentication (macOS has no `SO_PEERCRED`, requires `getpeereid` FFI) and protocol version compatibility — clearly larger complexity and attack surface.
sudoers + allow-list script achieves the same goal using the system's built-in authorization mechanism, and with **a narrower privilege scope** (only network-configuration operations are allowed). If stronger isolation beyond passwordless is needed later (e.g. SMJobBless signature checks), revisit per §14 P5.

> If a `run` automation action declares `elevated: true`, it does **not** go through the allow-list channel but still uses the `osascript` auth dialog —
> user scripts must be treated separately from network-configuration operations, guaranteeing the user is informed every time a privileged script runs.

## 9.5 Status-Bar Popup Panel (primary interaction entry)

The standard menu-bar app interaction: **left-click the icon to pop the panel, auto-collapse on blur, right-click for the native menu**.

### Window layout (`tauri.conf.json`)

| label | file | key config |
|-------|------|------------|
| `popup` | `popup.html` | `340×470`, `decorations: false`, `alwaysOnTop`, `skipTaskbar`, `visible: false` |
| `main` | `editor.html` | `760×580`, `center`, `visible: false` (shown on demand, no window at startup) |

Both windows are created at startup and only shown/hidden — the webview is **not rebuilt on every click** (guarantees instant open).

### Show/hide & positioning (`src-tauri/src/popup.rs`)

1. **Trigger**: `TrayIconBuilder::show_menu_on_left_click(false)` makes left-click stop popping the native menu and instead dispatch `TrayIconEvent::Click{Left, Up}` → `popup::toggle()`; right-click still shows the menu.
2. **Positioning**: take the event's `rect` (physical icon rectangle) → anchor = icon horizontal center + vertical bottom edge, then shift `y` down 6px; finally `clamp` using `current_monitor()`'s position/size to prevent the panel from going off-screen on edges or external displays.
3. **Blur-collapse**: in `Builder::on_window_event`, watch `WindowEvent::Focused(false)` with label `popup` → `popup::hide()`.
4. **Debounce (key detail)**: when clicking the icon to collapse the panel, blur fires a hide first, then the tray click opens it again — appearing as "one click flickers". `popup.rs` records the collapse moment with `LAST_HIDE: Mutex<Option<Instant>>` and ignores tray clicks within 300ms.
5. **macOS menu-bar form**: `set_activation_policy(ActivationPolicy::Accessory)` in setup hides the Dock icon; the editor window's "close" is intercepted by `CloseRequested` into `hide()` (`api.prevent_close()`), i.e. closing = retracting to menu-bar resident, not quitting.

### Panel content (`frontend/popup.html`)

Connection status dot + SSID, current profile, IPv4 / gateway / DNS / signal, privilege-channel badge (passwordless / per-auth), profile quick-switch list (click = `force_apply`), bottom "open editor / refresh / quit".
On each focus (when opened) it auto-refreshes via `get_status`, and also passively refreshes by subscribing to the `netsense://status` event.

### Points needing real-device verification (cannot verify locally)

- After `ActivationPolicy::Accessory` takes effect, whether `window.set_focus()` can give the panel keyboard focus, thus reliably triggering blur-collapse. If clicking outside on macOS does not collapse, append an "activate app" call after show.
- `show_menu_on_left_click` is named `menu_on_left_click` in some Tauri 2.x versions; rename per the compiler hint if it errors.
- The `rect` field of `TrayIconEvent::Click` exists only in newer versions; if absent, use the same event's `position` (click coordinates) as the anchor — `popup::toggle`'s parameters are unchanged.
- The tray `rect` is physical pixels under Retina; anchor conversion already handles physical pixels. If the panel is offset by half an icon width, the platform returned logical coordinates — convert by scale factor instead.

## 9.6 Three-Platform Implementation Reference (`platform/{macos,windows,linux}.rs`)

The upper layer (`main.rs` / `ipc.rs` / `core/*`) **depends only on `platform::Platform` and the `NetworkPlatform` trait**; the concrete platform is selected at compile time by `platform.rs` via `target_os` and re-exported uniformly:

```rust
#[cfg(target_os = "macos")]   pub use macos::{priv_channel, MacPlatform as Platform};
#[cfg(target_os = "windows")] pub use windows::{priv_channel, WindowsPlatform as Platform};
#[cfg(target_os = "linux")]   pub use linux::{priv_channel, LinuxPlatform as Platform};
```

| Capability | macOS | Windows | Linux |
|------------|-------|---------|-------|
| Wi-Fi interface discovery | fixed `en0` | `Get-NetAdapter` by `MediaType='Native 802.11'` | `nmcli -t -f DEVICE,TYPE dev status` finds `wifi` |
| Current SSID | `networksetup -getairportnetwork en0` | `Get-NetConnectionProfile.Name` | active connection name (`nmcli`) |
| IP/mask/gateway/DNS | `ipconfig` + `networksetup -getinfo` | one PowerShell JSON pull (`Get-NetIPAddress` / `Get-NetRoute` / `Get-DnsClientServerAddress`) | `nmcli -g IP4.*` |
| BSSID / signal | `airport -I` | `netsh wlan show interfaces` (**ASCII fields only**) | `nmcli -f IN-USE,BSSID,SIGNAL dev wifi list` |
| Gateway MAC | `arp -n <gw>` | `arp -a` matching gateway line | `ip neigh show <gw>` |
| Write IP/DNS | `networksetup -setmanual/-setdnsservers` | `netsh interface ipv4 set address/dnsservers` | `nmcli con mod ipv4.*` + `con up` |
| IPv6 toggle | `networksetup -setv6off/-setv6automatic` | `Enable/Disable-NetAdapterBinding ms_tcpip6` | `nmcli con mod ipv6.method` |
| Route | `route -n add/delete` | `New-NetRoute` / `Remove-NetRoute` | `ip route add/del` |
| Probe ICMP / HTTP | `ping -c1 -t` / `curl` | `ping -n1 -w` / `curl.exe` | `ping -c1 -W` / `curl` |
| Elevate = Direct | sudoers allow-list script (`sudo -n`, no dialog) | process already admin | `sudo -n` available |
| Elevate = Prompt | `osascript ... with administrator privileges` | UAC (`Start-Process -Verb RunAs`) | `pkexec` |
| Saved SSID list | `networksetup -listpreferredwirelessnetworks` | read WLAN config XML (`[xml]` parse) | `nmcli con show` filtered to `802-11-wireless` |
| Open log folder | `open` | `explorer` | `xdg-open` |

### Three key Windows backend designs (read before changing — known pitfalls)

1. **Read via PowerShell CIM, not `netsh` text**.
   On Chinese Windows, `netsh` output is **localized + OEM code page (CP936)**: field names become Chinese, values like "已连接"/"信号" are Chinese too, and decoding as UTF-8 corrupts them.
   CIM cmdlets return objects, language-independent; we uniformly inject `[Console]::OutputEncoding = UTF8` in `ps()` so Chinese-containing return values (SSID, adapter name) decode correctly.
2. **Exception: BSSID / signal percentage still come from `netsh` text, but only ASCII fields are extracted** (MAC hex, `NN%` digits). ASCII bytes are identical under CP936 and UTF-8, so unaffected by encoding; and these two lines have no CIM equivalent. **Do not** extract SSID the same way (SSID may be Chinese).
3. **Elevation commands always pass args as `@('a','b')` arrays, never string-concatenated**:
   `& netsh.exe @('interface','ipv4','set','address','name=Wi-Fi','static',...)`.
   Interface names with spaces/special chars are not re-split. The whole batch is rendered into a PowerShell script and handed to `Start-Process -Verb RunAs` via `-EncodedCommand` (UTF-16LE + base64, self-implemented, zero-dependency) for **one UAC covering all operations**.

> **Status cache**: `resolve_current_name()` asks SSID + gateway MAC + BSSID at once, but each read on Windows spawns a PowerShell process (hundreds of ms).
> `platform/windows.rs` uses a 1.2s-TTL snapshot cache `status_cached()` to absorb the cost; `invalidate_cache()` clears it immediately after a write.

### Cross-platform matcher traps (fixed)

MAC formats returned by each platform are inconsistent: Windows `arp -a` is `aa-bb-cc-dd-ee-ff`, macOS/Linux is `aa:bb:cc:dd:ee:ff`, and case is not unified either.
So `core/matcher.rs` passes **both sides through `platform::normalize_mac()`** (lowercase + colon), so any form written in config matches.
SSID comparison **stays case-sensitive** (802.11 SSID is itself case-sensitive).

## 10. i18n / Logging / Config Hot-Reload

### 10.1 i18n (`src-tauri/src/i18n.rs` + `i18n/*.json`)

- 5 languages (zh / en / zh-TW / ja / ko), **`en.json` is the baseline**; dictionaries are embedded into the binary at compile time via `include_str!`, so no file is read at runtime and no packaging omission can occur.
- Lookup order: current language → `en` → the key itself (**never panics**). `tf(key, args)` supports `{name}` placeholder substitution.
- **Key-parity check** (`check_parity()` returns missing/extra/empty, requiring all three to be 0) runs once at app startup; failure only warns, does not block startup.
  `cargo test` includes three cases guarding parity: `parity_ok_in_bundle` / `fallback_to_en_then_key` / `placeholder_replace`.
- Language switch: IPC `set_language` → write back to `config.language`; frontend `get_strings` pulls all strings at once, avoiding per-key invoke round-trips.
- Add new copy to all 5 languages together; delete from all 5 together.
- **Current scale: 79 keys × 5 languages**. All copy in `popup.html` / `editor.html` comes from the backend dictionary (templates no longer embed i18n objects), so parity covers all UI copy.

### 10.2 Logging (`src-tauri/src/log.rs`)

- Path: `<same dir as config>/logs/netsense-YYYY-MM-DD.log`, **daily rotation, keep 7 days**, cleaned at startup and at day boundaries.
- Global `OnceLock<Mutex<Logger>>` serializes writes, thread-safe; four levels `error/warn/info/debug`, `set_level` filters.
- Logs before `init()` degrade to stderr, so early-startup failures are not lost.
- `init(dir, true)`: the second arg is `to_stderr` — `true` in dev (terminal visible), can be `false` in release.

### 10.3 Config hot-reload (`main.rs::reload_watch_loop`)

- A background thread compares `config.json`'s mtime every 3 seconds; on change, reload + `validate()`.
- Validation failure → log error and **keep the old config**, so bad config cannot break the network.
- After reload, re-match the current identity and `apply_named(..., run_on_apply=false)`, i.e. **do not re-run `on_apply` automation** (avoids re-launching apps / re-running scripts).
- **Idempotency guard**: `AppState.applied_fp` records a fingerprint of "profile name + content serialization"; if unchanged, skip network push entirely.
  This way network-independent changes like switching UI language won't trigger a second `osascript` elevation dialog.
  After a health fallback to DHCP, the fingerprint is cleared (`None`) so the next reload re-pushes, instead of getting stuck on DHCP.

## 11. Build & Run

Three ways, pick one for your scenario. **If you just want a runnable package fast, use method three (CI) — zero local dependencies.**

| Method | Command | Prereq | Use for |
|--------|---------|--------|---------|
| 1. Local binary | `scripts/build-windows.ps1` (Win) / `cargo build --release` (mac/linux) | see table below | daily dev |
| 2. Local installer | `cargo tauri build` | additionally needs tauri-cli | need msi/dmg/AppImage |
| 3. Cloud build | push `v*` tag or manually trigger workflow | just a GitHub repo | **just want the artifact to test** |

### Per-platform prerequisites

| Platform | Required | Notes |
|----------|----------|-------|
| Windows | Rust(msvc) + **MSVC C++ Build Tools** + WebView2 | no MSVC substitute; check "Desktop development with C++", ~3–6 GB; another 5–10 GB on first build |
| macOS | Rust + Xcode CLT | WebView is the system's built-in WKWebView |
| Linux | Rust + `libwebkit2gtk-4.1-dev` `libgtk-3-dev` `librsvg2-dev` `libayatana-appindicator3-dev` `patchelf` | |

### Windows (recommended to use the script — it preflights before building)

```powershell
# preflight + bare exe (fastest; artifact at src-tauri\target\release\netsense.exe)
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1

# msi / nsis installer
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1 -Installer

# debug build with a console window (easier to see logs)
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1 -Debug
```

The script checks Rust / MSVC / Windows SDK / WebView2 / free disk in order and tells you exactly what to install, instead of letting you hit an unreadable `LNK1104` at link time.

### macOS / Linux

```bash
cargo build --release                 # bare executable
cargo tauri build                     # installer (needs tauri-cli)

# macOS first-time use: install the passwordless privilege channel (removes per-change auth dialog), needs sudo
sh scripts/install-priv-helper.sh
```

### Cloud build (CI)

`.github/workflows/build.yml` is a four-target matrix: `windows-x64` / `macos-arm64` / `macos-x64` / `linux-x64`.

```bash
git tag v0.3.0 && git push origin v0.3.0     # trigger build, produce draft Release + per-platform artifacts
# or on GitHub web: Actions → build → Run workflow (check release to also create a Release)
```

Inside the flow it first runs `python scripts/validate.py` (JSON / i18n parity / PAL boundary / trait coverage), then `cargo test` (matcher semantics + i18n parity); only after both pass does it compile and package.
Even without publishing a Release, each platform's bare executable is uploaded as an artifact for direct download and testing.

### First run

No window pops up at launch: the app resides in the tray, **left-click the icon** opens the popup panel, right-click opens the menu (show editor / open log folder / privilege channel / quit).
Config location: **`config.json` next to the exe** (falls back to the working directory if absent); copy `config.example.json` and rename to use.

> **Windows prompts UAC once on the first network change.** To remove it: launch once as administrator (after that the in-process privilege channel shows "no authorization needed"). If you don't want to stay admin, accept one UAC per network change — this is the peer design of macOS's `osascript` fallback channel.

## 16. Design Decision Record (confirmed baseline)

- Tech stack: **Tauri v2 (Rust)**, not Wails.
- Match conditions: **SSID / gateway MAC / BSSID are independent, AND, usable alone**.
- Switches: **health monitoring / whether to fall back / automation tasks are independent and orthogonal**.
- Health: **icmp/http/both**, `both` requires double-failure to declare dead; fallback = DHCP safety net.
- Automation: **netsetman-style route/launch/run**, triggered on `on_apply`/`on_revert`, `run` allow-list constrained.

### P3 done (three-platform universal)

> Goal changed from "macOS first" to "three platforms, one codebase".

- **PAL refactored into modules** (`platform.rs` → `platform/{macos,windows,linux}.rs`):
  - `platform.rs` keeps only the trait contract + shared types + shared utils (`run` / `poll_ssid_watch` / `parse_kv` / `extract_mac` / `normalize_mac` / `open_path`) + **compile-time platform selection** (`#[cfg(target_os)] pub use ... as Platform`).
  - `PrivChannel` semantics unified across platforms into `Direct` (passwordless/already-elevated, no dialog) and `Prompt` (per-auth), each platform maps to its local mechanism; `InterfaceStatus` gains `iface` (current wireless interface name).
  - **No concrete platform type name appears in the upper layer**: `main.rs` / `ipc.rs` / `core/*` use only `Platform` and the trait; this boundary is enforced by `scripts/validate.py` check #5.
- `platform/windows.rs` (new) — full Windows backend, see §9.6:
  - Read: one PowerShell JSON snapshot (interface name/SSID/IP/prefix/gateway/DNS/IPv6); BSSID and signal percentage via `netsh` but **ASCII fields only**.
  - Write: `netsh interface ipv4 set address/dnsservers` + `New-NetRoute`, all rendered as `& netsh.exe @('a','b')` array calls; the whole batch goes through `-EncodedCommand` + `Start-Process -Verb RunAs` for **one UAC covering all**.
  - Privilege channel: process already admin → `Direct`, otherwise → `Prompt`.
  - `list_known_ssids`: read WLAN config XML (`[xml]`), language-independent and correctly encoded.
  - Self-implemented base64 (`-EncodedCommand` needs UTF-16LE base64), **zero new dependencies**.
  - 1.2s-TTL status cache to avoid spawning multiple PowerShell processes per identity resolution.
- `platform/linux.rs` (new) — `nmcli` read/write + `ip route` + `ip neigh`; privilege prefers `sudo -n`, falls back to `pkexec`; correctly handles `nmcli -t` backslash escaping.
- `platform/macos.rs` — original `platform.rs` macOS part moved as-is, logic unchanged, now reuses shared `poll_ssid_watch` and `run`.
- `core/matcher.rs` — **fixed cross-platform MAC matching defect**: both sides through `normalize_mac()` (Windows `arp` uses hyphens, different case too), plus **7 unit tests** covering multi-condition AND / most-specific-wins / priority tie / no-match skip / gateway-MAC-only identification / normalization.

### Implementation notes diverging from baseline
- `probe.http` uses `curl` (system `curl.exe` on Windows) instead of reqwest (avoid new dependency); ICMP uses system `ping` (macOS BSD `-t` seconds / Windows `-w` ms / Linux `-W` seconds).
- **Module name `core` collides with the std crate `core`**: under Rust 2018 uniform paths, `use core::x` is ambiguous (E0659), so all imports must be explicit: `use crate::core::{matcher, health, automation}` (expression-path `log::info(...)` is unaffected).
  New Core Engine modules should follow this style.
- `InterfaceStatus` gains `Serialize` (IPC return needs JSON) and `gateway_mac` / `netmask` / `bssid` / `iface` fields.
- After health fallback, the `applied_fp` fingerprint is cleared: otherwise later hot-reloads would skip push due to "content unchanged", leaving the network stuck on DHCP.
- **Privilege model uses the system's built-in authorization** (macOS sudoers allow-list / Windows UAC / Linux sudo+pkexec), not the originally planned resident privilege daemon — rationale in §9.2 (narrower scope, no socket-auth surface).
- `watch_ssid` is adaptive polling (2s/5s) on all three platforms, **not event-driven**: macOS's CoreWLAN notifications need objc2 FFI and handling `CWInterface` notification object lifetime, Windows's `WlanRegisterNotification` likewise needs FFI; the payoff (skipping a subprocess every 2–5s) doesn't justify the complexity, deferred.
  The polling logic is extracted into shared `poll_ssid_watch`; switching to event-driven later only requires changing each platform's `watch_ssid` in one place.
- The frontend has no build tooling (no Vite/Svelte), still pure static HTML; `invoke` depends on `withGlobalTauri`.
  **Side effect (good)**: CI needs no Node at all, shorter build chain.

## 18. Build Environment Notes (why some environments can't build locally)

Tauri on Windows **officially requires the MSVC toolchain + Windows SDK** (the docs say "no substitute"), macOS packages must be compiled on macOS, and Linux needs the webkit2gtk dev library. So producing "one set of three-platform installers" inherently needs three environments.

Preflight results measured on a Windows machine (for you to judge which path to take):

| Check | Measured | Impact |
|-------|----------|--------|
| Rust toolchain | not installed (no `~/.cargo` / `~/.rustup`) | install first, ~0.5–1 GB |
| MSVC linker | **missing** (`VS2019` dir is an empty shell, `vswhere` finds no VC tools) | hard prereq for Tauri Windows build; install Visual Studio Build Tools (~3–6 GB) |
| Alternative | system has TDM-GCC (`x86_64-w64-mingw32`), can use `x86_64-pc-windows-gnu` | unofficial path, `webview2-com-sys` etc. risky under gnu |
| Disk | C: **164 MB** left, D: 2.8 GB, E: 4.0 GB | **decisive constraint**: after installing MSVC + Rust then compiling (first target ~2–5 GB) it will certainly fill |
| Network | crates.io / rust-lang.org / rsproxy all reachable | download isn't the bottleneck, disk is |

**Conclusion**: disk space can't fit the MSVC toolchain, so a local Windows installer is impossible. Feasible paths in recommended order:

1. **CI build (preferred)**: push the repo to GitHub, `git tag v0.3.0 && git push origin v0.3.0`, and `.github/workflows/build.yml` produces windows-x64 / macos-arm64 / macos-x64 / linux-x64 executables and installers on the cloud matrix. **Zero local dependency, no disk used, get all three platforms at once.**
2. **Local build**: first free ~10 GB, install Visual Studio Build Tools (check "Desktop development with C++") and Rust, then run `scripts\build-windows.ps1` (the script does the preflight for you).
3. **Verify code compiles only**: install Rust's `x86_64-pc-windows-gnu` target — `cargo check` **needs no linker**, only `windres` (TDM-GCC ships it), so `cargo check --target x86_64-pc-windows-gnu` validates types and dependency resolution but produces no executable. See `scripts/sandbox-bootstrap.sh`.
